# 商品到期提醒系统

一个简单实用的商品到期提醒应用，帮助您管理商品的保质期信息。

> 云端存储已从 LeanCloud 迁移到 **腾讯云开发 CloudBase**（LeanCloud 将于 2027 年 1 月 12 日停止对外服务）。

## 功能特点

### 1. 商品管理
- 支持EAN-13/8条码输入（适合扫码枪使用）
- 自动根据条码带出商品名称（需提前设置映射）
- 支持手动输入或通过生产日期+保质期自动计算到期日期
- 商品列表展示，包含条码、名称、生产日期、保质期、到期日期等信息

### 2. 条码映射
- 建立商品条码与商品名称的映射关系
- 输入条码时自动带出对应商品名称
- 编辑映射时自动同步更新商品列表中的商品名称
- 支持映射的添加、编辑和删除

### 3. 到期状态管理
- 自动计算商品到期状态，列表里直接显示「剩几天 / 过期几天」：
  - 正常：3个月以上
  - 1-3个月：即将到期预警
  - 1个月内：紧急提醒
  - 已过期：过期商品
  - 无有效期：单独标记，不会当成「正常」混在里面

### 4. 到期提醒
- 打开页面时，顶部横幅醒目列出已过期和 30 天内到期的商品
- 如果已经有商品过期，每天首次打开页面会弹出一次提示（每天最多一次，不会反复打扰）
- 横幅可点「知道了」当天不再显示，或点「只看这些」直接筛出临期商品
- 列表中已过期 / 30 天内到期的整行带底色，并自动排在最前面

### 5. 过期商品处置（保留原始记录）
- 过期或用不上的商品**不删除**，只标记处置方式：已用完 / 已丢弃 / 已退换 / 其他，可另填备注（如「长毛了整箱扔」）
- 处置后商品默认从列表隐藏，点「显示已处理」查看；搜索时也会被搜出来
- 已处理的商品不再计入到期提醒横幅、打开页面的弹窗和顶部概览统计，避免「处理完了还在催」
- 处置只是挂一个标记，条码 / 生产日期 / 有效期等原始字段一个都不改，随时可点「撤销处理」回到待处理列表
- 每行始终保留「删除」按钮，想彻底删掉仍然可以（删除也会同步到其他设备）

### 6. 页面布局与数据概览
- 页面从上到下：提醒横幅 → 一行概览 → 商品列表 → 添加商品（收起）→ 映射管理 → 数据区
- 概览是一行带色标签（共几条 / 正常 / 1-3个月 / 30天内 / 已过期 / 未填有效期 / 已处理），数字与列表行数对得上
- 商品列表放在最前面；「添加商品」默认收起成一行标题栏，点一下才展开

### 7. 数据管理
- **导出CSV**：将商品数据导出为CSV文件（含条码映射和处置信息，可直接当备份用）
- **导入CSV**：从CSV文件导入商品数据
- **清空数据**：一键清空所有商品和映射数据

> 导出的 CSV 在原有 8 列后追加了「处置方式 / 处置日期 / 处置备注」3 列。
> 旧版本导出的 8 列文件依然能正常导入，处置信息按「未处理」处理。

### 8. 数据同步
- 集成腾讯云开发 CloudBase 实现数据云同步功能（也可改用 GitHub 仓库存数据）
- 需要配置 CloudBase 环境 ID（详见下文「配置 CloudBase 数据同步」）
- 商品按内部唯一标识 `uid` 合并，同一商品的不同批次不会互相覆盖
- 每条记录带「最后修改时间」`updatedAt`，合并时**逐条比新旧、谁新用谁**：
  - 「同步数据」不会被本机旧副本覆盖掉云端的新状态（例如别的设备刚标记的处置）
  - 「获取最新数据」也不会抹掉本机刚改过、还没同步的记录
  - 两个方向都不丢数据，先点哪个按钮都不影响结果
- 老记录没有 `updatedAt`，用处置日期 `handledAt` 兜底判新旧，无需手工迁移
- **删除也会跨设备同步**：删除时不把云端那条抹掉，而是留一条带 `deletedAt` 的「墓碑」，
  合并时墓碑和记录一起比时间：
  - 墓碑更新 → 记录被删掉，别的设备手里的旧副本也一并消失（不会再「删了又回来」）
  - 记录更新 → 这条在别处被改过，以改动为准，墓碑作废（删完还能救回来）
  - 删除后会自动把墓碑推一次云端；万一当时没推上去（离线 / 没填令牌），下次点「同步数据」会补上
  - 只删点中的那一条，同条码的其他批次不受影响
- 墓碑存在原来的商品 / 映射集合里（就是带 `deletedAt` 的文档），不用新建集合，也不用额外配权限
- **映射永久保留**：删除商品只影响商品本身，条码-名称映射不会被连带删掉。
  映射要单独删，去「条码-名称映射管理」里操作即可（映射的删除同样会同步到其他设备）

## 使用方法

### 1. 基本使用
1. 打开 `index.html` 文件
2. 在商品条码输入框中输入或扫描条码
3. 选择生产日期和保质期，系统会自动计算到期日期
4. 点击"添加商品"按钮保存

### 2. 配置条码映射
1. 在"条码-名称映射管理"区域
2. 输入商品条码和对应的商品名称
3. 点击"添加映射"按钮保存
4. 之后输入该条码时，商品名称会自动填充

### 3. 数据导入导出
- **导出**：点击"导出CSV"按钮，系统会生成包含所有商品数据的CSV文件
- **导入**：点击"导入CSV"按钮，选择要导入的CSV文件

### 4. 配置 CloudBase 数据同步

> 注册和配置的全流程约 10 分钟，个人使用有免费额度。

1. 打开 https://tcb.cloud.tencent.com/ ，注册腾讯云账号并完成**个人实名认证**
2. 创建一个**环境**，记下生成的**环境 ID**（形如 `xxx-1a2b3c`）
3. 控制台「身份认证」中开启 **匿名登录**
4. 新建两个集合：`Product`（商品）与 `Mapping`（条码映射）
5. 把两个集合的权限设置为 **「所有用户可读写」**
   - 默认权限是「仅创建者可读写」，匿名登录下每台设备算一个独立用户，会导致换设备看不到数据
6. 在 `script.js` 中把 `ENV_ID` 替换为你的环境 ID：
   ```javascript
   const ENV_ID = 'your-env-id'; // 替换为你的 CloudBase 环境 ID
   ```
7. 打开页面后，点击「同步数据」把本地数据上传到云端，或点击「获取最新数据」从云端拉取

### 5. 从 LeanCloud 迁移已有数据

1. 在 LeanCloud 控制台「数据存储 → 导入导出」中，把 `Product` / `Mapping` 导出为 JSON
2. 在 CloudBase 控制台「数据库」中选择对应集合 → 「导入」，上传 JSON 文件
3. 若字段名不一致，按下面的规则调整后再导入：

| LeanCloud 字段 | CloudBase 字段 | 说明 |
|---|---|---|
| `objectId` | `_id` | 文档唯一 ID |
| `createdAt` | `_createTime` | 创建时间 |
| `updatedAt` | `_updateTime` | 更新时间 |
| `barcode` / `productName` 等业务字段 | 保持不变 | — |

> 提示：如果数据量很少，也可以直接在浏览器里点「获取最新数据」前，先手动把数据敲进新系统；或者先导出 CSV，在 CloudBase 里重新录入后用「同步数据」上传。

## 项目结构

```
product-expiry-reminder/
├── index.html              # 主页面文件
├── styles.css              # 样式文件
├── script.js               # JavaScript功能实现
├── html5-qrcode.min.js     # 扫码库（本地文件，勿删）
└── README.md               # 项目说明文档
```

> 注意：扫码库必须和页面一起部署。它之前从 CDN 加载，国内网络经常加载失败，已改为本地文件；
> 如果只上传 html/css/js 而漏掉 `html5-qrcode.min.js`，扫码功能会直接失效。
> （原来还有一个 `chart.umd.js` 图表库，已随柱状图一起删除，省下 205KB。）

## 技术实现

- **前端框架**：纯HTML/CSS/JavaScript，无框架依赖
- **图表库**：Chart.js
- **云存储**：腾讯云开发 CloudBase（可选）
- **本地存储**：localStorage

## 注意事项

1. 请确保在现代浏览器中使用（推荐Chrome、Firefox、Edge等）
2. 条码映射功能需要提前设置才能自动带出商品名称
3. 首次使用时，需要在 `script.js` 中配置 CloudBase 环境 ID 才能使用数据同步功能
4. 导入CSV文件时，请确保格式与导出的CSV文件格式一致
5. 安全问题：`ENV_ID` 等配置会随代码公开，请勿把云平台的密钥（SecretId / SecretKey）写进前端代码

## 故障排除

### 条码无法自动带出商品名称
- 检查条码是否已添加到映射列表
- 确保条码输入正确，无多余空格

### 在 A 设备删掉的商品，B 设备上还在（或同步后又回来了）
- B 设备点一次「获取最新数据」即可，删除标记会跟着合并过去
- 如果 B 设备本地那条在删除之后又被改过（标记处置、撤销处置等），会以改动为准、记录保留 —— 想彻底删掉就在 B 设备上再删一次
- 确认删除时页面是连通的：删除会顺带推一次云端，失败时页面会提示「下次点同步会补上」

### 数据同步失败
- 检查 `script.js` 中的 `ENV_ID` 是否已替换为你的 CloudBase 环境 ID
- 检查 CloudBase 控制台是否已开启「匿名登录」
- 检查 `Product` / `Mapping` 两个集合的权限是否设置为「所有用户可读写」
- 浏览器控制台按 F12 查看具体报错信息
- 确保网络连接正常

### 添加商品的表单不见了
- 它默认是收起的，点一下绿色标题栏「添加商品」即可展开；从列表点「编辑」也会自动展开
- 展开后光标会自动落在条码框，扫码枪可以直接扫

### v1.3.2
- **修复删除无法跨设备同步**：删除过去只是把记录抹掉（云端那份直接删库），云端从此没有任何线索说明「这条是被删的」，另一台设备手里那份旧副本一同步就把它原样带回来。现在删除改为留一条墓碑（带 `deletedAt` 的删除标记），同步时墓碑和记录一起比时间，谁新谁赢
- 商品与条码映射的删除都走同一套规则；删除后会自动把墓碑推一次云端，失败也会在下次「同步数据」时补上
- **映射改为永久保留**：以前删商品会顺手把云端的同名映射也删掉（本机那份却留着，下次同步又带回来，等于白删）。现在删商品只删商品，映射不受影响，要删映射请在「条码-名称映射管理」里单独操作
- 只删点中的那一条，同条码的其他批次不受影响；老数据（云端那条没有 `uid`）靠「条码 + 生产日期」认领，无需迁移
- 墓碑存放在原有的商品 / 映射集合里，不用新建集合或额外配置权限
