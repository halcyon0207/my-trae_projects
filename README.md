# 商品到期提醒系统

扫条码记录商品的生产日期与保质期，临期和过期自动推送到微信。纯前端页面 + 两个云函数，个人使用零成本。

```text
手机 / 电脑浏览器（页面）
        │  带「访问口令」
        ▼
云函数 product-api  ──(GitHub 令牌，只在云端)──▶  私有仓库 product-expiry / data.json
        ▲
        │
云函数 expire-notify（每天早上 7:30）
        │
        └──▶ PushPlus ──▶ 微信
```

数据只有一份（仓库里的 `data.json`），**浏览器里没有任何仓库令牌**，所有读写都经过云函数：

- 口令不对 → 接口直接拒绝（数据不会被人随便读走或清空）
- 两台设备同时改 → 服务端先合并再写入，不会互相覆盖
- 页面部署在 GitHub Pages 还是腾讯云都读同一份数据，不会再出现「换个网址看到旧数据」

## 页面入口与默认域名的坑

**页面入口：<https://halcyon0207.github.io/my-trae_projects/>**

腾讯云那两个默认域名（`*.tcloudbaseapp.com` 静态托管、`*.app.tcloudbase.com` 云函数 HTTP 访问服务）
从 2026-09-16 起打开页面会变成**下载一个 HTML 文件**，原因是平台在**所有成功回源的响应**上加了：

```
content-disposition: attachment
```

这不是本项目配置的问题，逐条排除过：

| 排查项 | 结果 |
|---|---|
| 对象元数据（COS `headObject`） | 干净，没有 Content-Disposition |
| 显式给对象设 `Content-Disposition: inline` | 被平台覆盖成 `attachment` |
| 云函数自己返回 `Content-Disposition: inline` | 同样被覆盖成 `attachment` |
| 网关自己产生的 404 | **没有**这个头（所以只有真回源的内容受影响） |
| COS 源站直连（绕过 CDN） | 也带这个头 |
| 控制台「静态托管安全配置」 | 只有防盗链 / IP 黑白名单 / IP 限频三项，没有强制下载开关 |
| 官方文档 | 只说明「默认域名仅用于开发测试，生产环境应绑定自定义域名」 |

也就是说：**默认域名 + 本环境的组合下，平台不允许直接以网页形式打开内容。**
目前用的绕开办法是页面改放 GitHub Pages（响应头干净、已验证）；
CloudBase 只负责数据接口与定时推送 —— 这两件事不受影响，因为浏览器对 `fetch()` 的响应不看这个头。

备份入口：`cloudfunctions/site`（把页面文件直接由云函数吐出，映射在 `/app`）。
它是给「以后绑了自定义域名或平台策略解除」准备的，现在打开同样是下载，不用管它。

> 如果你以后有域名：在静态托管里绑自定义域名（大陆节点需备案），
> 页面入口就能回到腾讯云，`content-disposition` 的问题也随之消失。

## 功能特点

### 0. 到期主动推送
- 每天早上 7:30（北京时间）自动扫一遍商品，把过期 / 临期商品推到微信
- 推送节奏（不是每天都推，避免最后被无视）：
  - **已过期 / 今天到期** → 每天都推，这是真该处理的
  - **只是临期（1 ~ 30 天）** → 每周一汇总推一次
  - **什么都没有** → 默认每周一推一条「今天没有临期或过期商品，请放心」（可配成每天或从不推）
  - **运行失败** → 立刻推一条明确写着「运行失败」的消息（否则「出错」和「当天没事」在微信里长得一样，你永远不会发现漏推了）
- 推送通道：**PushPlus**（免费，需实名一次）—— 详见 `cloudfunctions/expire-notify/README.md`

### 1. 商品管理
- 支持 EAN-13/8 条码输入（配合扫码枪），也可以直接用手机摄像头扫
- 自动根据条码带出商品名称（需提前在「条码-名称映射」里设置）
- 可手动输入有效期，也可以用「生产日期 + 保质期」自动算出来
- 列表展示条码、名称、生产日期、保质期、有效期，并直接显示「剩 N 天 / 过期 N 天」

### 2. 条码映射
- 建立条码与商品名称的对应关系，输入条码时自动带出名称
- 编辑映射会同步更新已有商品的名称
- 映射永久保留：删商品不影响映射，要删映射请单独操作

### 3. 到期状态
- 列表里直接显示剩余天数，并按紧急程度分档：
  - 正常：3 个月以上
  - 1-3 个月：即将到期
  - 1 个月内（默认 30 天，阈值由云端下发）：紧急提醒
  - 已过期 / 未填有效期：单独标记，不会混进「正常」里

### 4. 到期提醒（页面内）
- 打开页面时，顶部横幅列出已过期和临期商品，可点「只看这些」直接筛出来
- 有商品过期时，每天首次打开会弹一次提示（每天最多一次）
- 列表里过期 / 临期整行带底色，并自动排在最前面

### 5. 过期商品处置（保留原始记录）
- 过期或用不上的商品**不删除**，只标记处置方式：已用完 / 已丢弃 / 已退换 / 其他（可填备注）
- 处置后默认从列表隐藏，点「显示已处理」查看，搜索也能搜到
- 已处理的不再计入横幅、弹窗和顶部统计（避免「处理完了还在催」）
- 条码、生产日期、有效期等原始字段一个都不改，随时可「撤销处理」

### 6. 数据管理
- **导出 CSV**：商品 + 映射 + 处置信息，可直接当备份
- **导入 CSV**：兼容老版本导出的 8 列文件（处置信息按未处理处理）
- **清空数据**：一键清空商品和映射

### 7. 数据同步
- 「同步数据」＝ 把本机改动上传（服务端与云端合并后写回，不会覆盖别的设备刚改的内容）
- 「获取最新数据」＝ 只读云端并合并回本机；如果本机有没上传的改动，会提示你点「同步数据」
- 商品按内部唯一标识 `uid` 合并，同条码的不同批次互不覆盖
- 每条记录带最后修改时间 `updatedAt`，合并时逐条比新旧，谁新用谁
- **删除也会同步**：删除不是抹掉记录，而是留一条带 `deletedAt` 的「墓碑」，
  别的设备手里的旧副本会被它删掉；删完又在别处改过的，以改动为准（删了还能救回来）
- 老记录没有 `updatedAt`，用处置日期 `handledAt` 兜底，无需手工迁移

## 部署

> 日常改动只需要跑一条命令：`powershell -File scripts/deploy.ps1 -Hosting`

### 首次部署要准备的东西

| 东西 | 用途 | 放哪儿 |
|---|---|---|
| PushPlus token | 推送到微信 | `.env.local` 的 `PUSHPLUS_TOKEN` |
| GitHub PAT（`repo` 权限） | 云函数读写私有仓库 | `.env.local` 的 `GITHUB_TOKEN` |
| 访问口令 API_KEY | 页面调用接口的凭据 | `.env.local` 的 `API_KEY`（随机生成） |

`.env.local` 已被 `.gitignore` 忽略，`cloudbaserc.json` 里用 `{{env.XXX}}` 引用它，
所以**令牌不会进代码库，也不会因为重新部署而丢**。

### 部署脚本做了什么

1. 跑单元测试（`tests/*.test.js`）
2. 把 `shared/*.js` 复制到各云函数的 `lib/`（云函数没法 require 项目外层目录）
3. 把 `index.html` 里的 `?v=` 换成当前时间戳 —— 静态托管的 `Cache-Control` 是一年，
   不改版本号浏览器和 CDN 会一直用旧脚本（这个坑踩过）
4. 部署 `product-api` 与 `expire-notify`，并按 `cloudbaserc.json` 重新写入环境变量
5. 创建 HTTP 访问服务（`/api` → `product-api`）
6. 加 `-Hosting` 时，再把静态页面发布到 CloudBase 静态托管

### 关于密钥的另一条路（可选）

云函数的环境变量是在控制台里加密保存的；如果哪天想换更严的方式，
可以用「云开发密钥管理」或 KMS 托管，改 `cloudbaserc.json` 的取值方式即可，代码不用动。

## 开发

```bash
npm test                 # 单元测试（日期 / 合并 / CSV / 页面能否正常加载）
npm run smoke            # 接口冒烟测试（需要 .env.local 里的 API_KEY）
```

## 常见问题

### 打开腾讯云那个域名，浏览器变成下载一个 HTML 文件
平台的默认域名策略，不是你改坏了什么 —— 详见上文「页面入口与默认域名的坑」。
直接用 GitHub Pages 那个入口即可；数据接口和微信推送都正常，不受影响。

### 忘了访问口令 / 想换一个
口令在 `.env.local` 的 `API_KEY`。改完跑一次 `npm run deploy` 即可；页面会提示口令失效，
重新输入新口令就行（浏览器控制台执行 `localStorage.removeItem('apiKey')` 可以强制重新输入）。

### 微信没收到推送
1. 看当天是不是「只需要周一汇总」的日子（普通临期只在周一推）
2. 函数出错时会单独推一条「运行失败」，所以「没有任何消息」＝「当天确实不用推」
3. PushPlus 限制：同一内容 1 小时内最多 3 条，重复测试可能被拒（属正常风控）
4. 超过 3 天没收到任何消息，就去 CloudBase 控制台看 `expire-notify` 的调用日志

### 页面报「访问口令不正确」
口令与云端不一致（例如换过环境）。重新输入即可，不会影响本机已有数据。

### GitHub 令牌过期
云函数会报「读取仓库失败（HTTP 401）」，并把这个错误推到你微信上。
去 GitHub 重新生成 PAT，改 `.env.local` 的 `GITHUB_TOKEN`，再跑一次 `npm run deploy`。

### 改了 css / js 但页面没变
`.gitignore` 挡不住缓存：静态托管的 js/css 缓存是一年。用 `npm run deploy:hosting`
（会自动改 `?v=`），或者手动打开无痕窗口验证。

### 手机扫码扫不出来
把条码横放，镜头离 10~15 厘米；对不准时点一下画面重新对焦，暗处可开补光灯。
